Como funciona a simulação CFD do wiebepy

A simulação CFD do wiebepy resolve o escoamento 3D compressível e transiente dentro do cilindro durante o intervalo de válvulas fechadas, com a combustão representada por uma fonte de calor prescrita pela função Wiebe de 1 a 5 estágios já calibrada no ensaio de pressão.

O encadeamento é o seguinte. Primeiro, o modo 0-D ajusta a curva de pressão medida e devolve os coeficientes de cada estágio (β, θ0, Δθ, m, a) e a razão de compressão. Esses coeficientes alimentam a fonte térmica, que converte a taxa de queima em potência:

Q̇(t) = mf · PCI · (dxb/dθ) · (dθ/dt),   com dθ/dt = 6 · rpm [°/s]

A derivada dxb/dθ vem da mesma implementação usada no 0-D, sem duplicação da formulação.

A fonte é entregue ao solver como densidade volumétrica q''' = Q̇/V₀(θ), e não como potência total, porque assim ela permanece conservativa com malha móvel e em execução paralela: o solver aplica a densidade sobre os volumes atuais das células. O fechamento é verificado em cada caso pela identidade ∫Q̇dt = mf·PCI·Δxb; no caso de exemplo o erro relativo é de 2×10⁻⁴.

A solução das equações de conservação é feita pelo OpenFOAM 13 (foamRun, solver fluid), executado no WSL2 ou em Linux. A geometria é um cilindro simplificado com pistão plano, cuja cinemática biela-manivela usa exatamente os mesmos parâmetros do modelo 0-D. O avanço é controlado em ângulo de manivela, com passo entre 0,01° e 0,5° e Courant máximo de 0,25.

Ao final, o wiebepy extrai as séries 0-D (pressão média volumétrica, temperatura, perda de calor nas paredes, trabalho indicado) e gera um relatório HTML autocontido com proveniência, balanços e comparação com o ensaio por faixa de ângulo.

Escopo, declarado em todas as saídas: a taxa de queima é imposta, portanto a cinética química, a frente de chama, o knock e as emissões não são resolvidos, e a comparação com o ensaio é diagnóstica, não validação independente, já que a Wiebe foi calibrada com os mesmos dados. O que o CFD acrescenta ao 0-D é a distribuição espacial de velocidade, pressão e temperatura e a troca de calor resolvida nas paredes.

Instalação do solver, preparação e execução de casos: seção CFD (opcional).

1. Instalação

Requer Python 3.11 ou superior (Windows, Linux ou WSL2). Crie um ambiente virtual antes de instalar, dentro da pasta do projeto:

cd wiebepy
python -m venv .venv
.venv\Scripts\activate            # Windows (Linux/WSL2: source .venv/bin/activate)
python -m pip install --upgrade pip
pip install -e ".[numba,dev]"     # núcleo + Numba (rápido em CPU) + pytest
pip install cupy-cuda12x          # opcional: só com placa NVIDIA

Confira:

wiebepy --devices                 # hardware e backends disponíveis
python -m pytest -m "not slow"    # testes rápidos (~20 s)
Sem instalar: dentro da pasta do projeto, python main.py … faz o mesmo que wiebepy ….
“wiebepy não é reconhecido”: o pacote não está instalado no Python que o terminal usa. Ative o .venv (o prompt mostra (.venv)) e rode pip install -e . de novo, ou use python main.py. Se o PowerShell bloquear a ativação, rode uma vez Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

2. Primeira análise

Avalie um modelo sem dados, numa grade de −20° a 100°:

wiebepy --stages 3 --theta-min -20 --theta-max 100 --theta-step 0.1 --plot

Ajuste um modelo aos dados sintéticos que acompanham o projeto:

wiebepy --stages 2 --optimize --input examples\data\synthetic_2stage.csv ^
        --fit-target xb --save-plots --output results\primeiro

Na tela aparecem os parâmetros de cada estágio, o objetivo de cada run e as métricas (RMSE, R², AIC, BIC, Durbin-Watson). Os parâmetros verdadeiros dos dados sintéticos estão em examples\data\true_parameters.json — compare.

Comandos prontos para todos os casos: wiebepy --help-examples.

pip install -e ".[gui]"     # uma vez: Streamlit

2c. Ajustar a curva de PRESSÃO (dados de ensaio)

Se o seu arquivo tem ângulo × pressão do cilindro (como o ensaio do Double Wiebe), use o modo pressão: o wiebepy ajusta a pressão com o mesmo modelo 0-D do Double Wiebe, com 1 a 5 estágios de liberação de calor.

  1. GUI: página Dados → Tipo de dado = Pressão do cilindro; escolha a unidade do ângulo (radianos no ensaio) e da pressão (bar); confira o motor em “Motor (geometria e combustível)”.
  2. Página Ajuste: escolha N e clique em Iniciar ajuste. O RMSE mostrado é o da referência solve_ivp.
  3. Página Comparação: compare 1, 2 e 3 estágios.
wiebepy --stages 2 --optimize --input ensaio.txt --input-type pressure --pressure-unit bar
Carregar um arquivo de pressão como “Fração queimada” dá erro: xb precisa estar entre 0 e 1.

3. O modelo e seus parâmetros

zj = (θ − θ0,j) / Δθj
xb(θ) = Σj βj [1 − exp(−aj zjmj+1)]   (termo = 0 se θ < θ0,j)
dxb/dθ = Σj βj aj(mj+1)/Δθj · zjmj · exp(−aj zjmj+1)
ParâmetroSignificadoUnidadeRestrição
β (beta)fração da massa queimada no estágio–0 ≤ β ≤ 1, Σβ = 1
θ0 (theta0)início do estágio° (ou rad)ordenados no ajuste
Δθ (duration)duração do estágio° (ou rad)> 0
mforma (pequeno = início abrupto)–> 0
aeficiência (6.908 ⇒ 99.9 % em Δθ)–fixo, ou ajustado com --fit-a

1 estágio = single-Wiebe; 2 = double-Wiebe (pré-misturada + difusão); 3 a 5 estágios representam fases adicionais (ex.: queima tardia). Formulação completa: wiebepy --help-model.

4. Preparar os dados

Arquivo .csv, .txt, .dat ou .json com o ângulo e a fração queimada e/ou a taxa de queima:

theta,xb                theta,dxb_dtheta           theta,xb,dxb_dtheta,sigma
-20,0.000               -20,0.0000                 ...
-19,0.000               -19,0.0000
  • Separador detectado automaticamente; linhas com # são ignoradas.
  • Sem cabeçalho: 2 colunas = θ, xb; 3 colunas = θ, xb, dxb/dθ.
  • Coluna weight (ou sigma, com peso = 1/σ²) opcional, para --objective wrmse.
  • θ em graus por padrão; use --angle-unit rad se estiver em radianos.
  • xb deve estar normalizado entre 0 e 1 (o programa avisa se não estiver).

5. Ajustar N estágios

wiebepy --stages 3 --optimize --input dados.csv --runs 10 --save-plots --output results\fit3
OpçãoPara quê
--fit-target xb | dxb | bothsérie ajustada; both usa as duas, normalizadas (padrão: as disponíveis)
--objective rmse | mse | mae | see | wrmsefunção objetivo
--fit-aajusta também aj
--population, --iterationstamanho do PSO (padrão 100 × 1000)
--runs, --seedruns independentes e semente (reprodutível)
--config arquivo.yamltodas as opções num arquivo (ver examples\)

Cada run faz PSO seguido de refinamento local a partir dos 5 melhores pontos distintos do enxame. O resultado final é o melhor run.

6. Escolher o número de estágios

wiebepy --compare-stages 1 2 3 4 5 --input dados.csv --runs 10 --save-plots --output results\comparacao

O programa ajusta cada N e mostra uma tabela com RMSE, MAE, SEE, R², ΔAIC, ΔBIC, Durbin-Watson, erro de validação cruzada e número de avisos, seguida de uma recomendação.

Não escolha pelo menor RMSE. Mais estágios sempre reduzem o erro de treino. A recomendação usa o menor N cujo erro de validação cruzada fica a até 5 % do melhor e que não tem estágios desprezíveis ou coincidentes. AIC/BIC são indicativos: supõem resíduos independentes, o que não vale para curvas de xb. Um Durbin-Watson ≈ 2 indica que o modelo já captura a estrutura dos dados (resíduo ≈ ruído).

Exemplo com dados de 3 estágios verdadeiros: o RMSE continua caindo até N = 5, mas a validação cruzada estabiliza em N = 3, o BIC é mínimo em 3 e os modelos 4 e 5 geram avisos de estágios coincidentes — recomendação: 3-Wiebe.

7. Runs e avisos

O ajuste de vários estágios tem ótimos locais. Por isso cada ajuste roda vários runs (padrão 5; para N ≥ 3 prefira 10 ou mais). O arquivo run_statistics.csv mostra best, mean, std, median e worst do objetivo; parameters.csv traz média e desvio de cada parâmetro entre runs.

Avisos de identificabilidade (lista completa em warnings.txt):

AvisoO que significa
Stage 4 contributes less than 0.5%estágio sobrando — use menos estágios
theta0_2 and theta0_3 are nearly identicaldois estágios começam juntos; se “redundant”, são praticamente o mesmo
parameter m_5 reached upper boundo ótimo pode estar fora dos limites — revise-os (seção bounds)
varies strongly between runsparâmetro mal determinado pelos dados
strongly correlated (rho = …)dois parâmetros se compensam; não interprete-os isoladamente

8. CPU paralela e GPU

--backendDescrição
auto (padrão)mede os disponíveis com o seu problema e usa o mais rápido
numbacompilado, com --workers threads — o mais rápido em CPU nas medições
numpyvetorizado, 1 núcleo; com --runs e --workers, os runs rodam em processos paralelos
multiprocessingdivide o enxame entre processos; só compensa em problemas muito grandes
cupy ou --gpuGPU NVIDIA; compensa com enxames × pontos grandes

Sem GPU (ou sem CuPy/Numba) o programa avisa e usa o próximo backend disponível — nunca para por isso. Meça na sua máquina: wiebepy --benchmark --workers 8.

--precision float32 acelera a GPU, mas torna a busca menos precisa; use float64 (padrão) para resultados finais.

No modo pressão o results.csv traz ainda as colunas P_sim_wiebe{k}_kPa e residual_wiebe{k}_kPa (k = N−1 … 1): modelos reduzidos que partem dos k primeiros estágios do ajuste com β renormalizado e são refinados por mínimos quadrados — cada curva é um k-Wiebe de fato ajustado ao ensaio, não um truncamento arbitrário (diagnóstico do que cada estágio adicional acrescenta; para comparação completa use --compare-stages). Os gráficos plots\pressure_stages_comparison.png (pressão × ângulo) e plots\pv_diagram_stages_comparison.png (P–V) sobrepõem o ajuste N, os modelos reduzidos e o ensaio; parâmetros de cada modelo reduzido em results.json.

10b. CFD (opcional) — escoamento 3D no cilindro

Página CFD (opcional): gera e executa casos OpenFOAM 13 (no Windows, via WSL2) com a liberação de calor prescrita pela Wiebe calibrada — 1 a 5 estágios, combustíveis H₂, CH₄ (puro), etanol e diesel. Não prevê cinética química, frente de chama nem emissões; os resultados 3D são condicionados à curva Wiebe informada. O restante do programa não depende do CFD, e desabilitá-lo não apaga resultados.

  1. Instalar o solver (uma vez): o OpenFOAM não vem do pip — pip install -e ".[cfd]" instala só dependências Python (PyYAML).
    1. WSL2 — PowerShell como administrador (Windows 11): wsl --install -d Ubuntu-22.04, depois wsl --version deve listar kernel WSL2 (não WSL1). Se reclamar de virtualização, ative na UEFI/BIOS.
    2. OpenFOAM 13 dentro do Ubuntu 22.04 (guia oficial openfoam.org/download/linux): sudo sh -c "wget -O - https://dl.openfoam.org/gpg.key | apt-key add -"; sudo add-apt-repository http://dl.openfoam.org/ubuntu; sudo apt update && sudo apt install openfoam13.
    3. Verificar: wiebepy cfd doctor lista as distribuições WSL2 e, para cada uma, o OpenFOAM detectado (/opt/openfoam*, foamRun, gcc, mpirun) e a versão. A execução usa wsl.exe -d <distro> e o caso é lido/escrito direto no projeto via /mnt/c/... — não é preciso copiar. Sem WSL2/solver, só os comandos CFD ficam indisponíveis (diagnóstico, nunca fallback silencioso). Guia completo (incl. Linux nativo): docs/cfd/install.md.
  2. Configurar: motor (mesmos parâmetros dos modos 0-D), janela angular (válvulas fechadas), condições iniciais, paredes, turbulência, combustível e origem dos estágios Wiebe (modelo atual ou model.json).
  3. Preparar → caso gerado para inspeção (estado Preparado).
  4. Validar → verifica arquivos, geometria e solver (estado Validado).
  5. Executar → log do solver ao vivo; Cancelar execução interrompe inclusive os processos MPI, preservando logs e resultados parciais. Processo terminou ≠ convergiu: confira o fechamento de energia no relatório.
  6. Relatório HTML → arquivo autônomo com proveniência completa (versões, parâmetros, malha, limites científicos) e os resultados p̄×θ, T̄×θ, trabalho indicado, perda às paredes e balanço de energia. Os resultados nunca são apresentados como predição independente de combustão — a fonte é a Wiebe prescrita.

Rodando um exemplo — caso de referência (case_006)

Para rodar um exemplo você só edita um arquivo; os outros dois são referenciados por ele. Os 3 arquivos que entram em jogo:

ArquivoPapelVocê edita?
examples/config_cfd_equivalencia.yaml Config do caso (motor + CFD) — é o único que o CLI recebe Só se quiser um diretório novo — senão usa --output
examples/model_cfd_calibrated.json Fonte Wiebe — já apontado dentro da config (wiebe.model) Não
examples/data/ensaio_P_exp_carga3_45.txt Ensaio experimental para o diagnóstico — já apontado (comparison.experimental) Não

A sequência (4 comandos + 1 verificação):

wiebepy cfd doctor                # 0. uma vez: confere WSL2 + OpenFOAM 13
wiebepy cfd prepare  --config examples/config_cfd_equivalencia.yaml \
    --output results/cfd/meu_caso   # 1. gera o caso (NÃO executa)
wiebepy cfd validate --case results/cfd/meu_caso   # 2. valida
wiebepy cfd run      --case results/cfd/meu_caso   # 3. executa (WSL2/OpenFOAM; ~2-3 min na malha 24x36)
wiebepy cfd report   --case results/cfd/meu_caso   # 4. relatório HTML com p×θ, p×V e comparação com o ensaio

O --output sobrescreve o case_directory da config — assim você não toca em arquivo nenhum e não sobrescreve o case_006 arquivado. O que cada comando produz:

  • prepare → results/cfd/meu_caso/ completo (system/, constant/, 0/, case_config.yaml — este último registra TUDO: procedência da fonte, propriedades, energia, hipóteses); você pode inspecionar antes de rodar.
  • validate → estado do caso vira Validado (só caso validado executa — é o gate que já impediu erros de caminho no case_013).
  • run → logs/foamRun.log, séries em postProcessing/, estado Concluído.
  • report → report.html dentro do diretório do caso — é esse que você abre no navegador.

Variantes úteis sem editar arquivo:

  • Sem combustão (motored): acrescente --no-heat ao prepare.
  • Multicomponente (R1): precisa de config própria — copie examples/config_cfd_multicomponent.yaml (já tem gas.model: multicomponent_inert).
  • GUI: streamlit run src/wiebepy/gui/app.py → aba CFD já abre casada com o case_006; os botões são os mesmos quatro passos.

Lembrete de leitura do resultado: o report.html compara com o ensaio de forma diagnóstica (mesma rotação, mesma energia) — o que ele diz é onde o modelo diverge do ensaio e por quê, não "o modelo foi validado".

Rodando um exemplo na interface gráfica (GUI)

Abertura (requer pip install -e ".[gui]"): wiebepy --gui — abre no navegador (localhost:8501) — ou streamlit run src/wiebepy/gui/app.py. Escolha a página CFD no menu lateral. O passo a passo, com os botões na ordem:

  1. Verificar o ambiente (uma vez): no expander Diagnóstico do ambiente (doctor), botão Executar diagnóstico — equivale ao wiebepy cfd doctor (confere WSL2, OpenFOAM, foamRun, mpirun). Se o OpenFOAM estiver instalado mas o código ainda não estiver conectado a ele (a linha Conexão mostra nenhuma), clique Conectar OpenFOAM ao código: o botão detecta a instalação, verifica que o foamRun executa de verdade (probe -help — detecção por diretório pode achar instalação quebrada), grava a conexão em ~/.wiebepy/cfd_env.json e ajusta automaticamente a Distribuição WSL2 do formulário — procurando primeiro na distro configurada e, sem instalação lá, usando a melhor de qualquer distro. Na CLI o equivalente é wiebepy cfd doctor --connect. A conexão sobrevive ao reinício da sessão (o padrão da distro passa a vir da conexão gravada).
  2. Escolher o diretório do caso — o primeiro ajuste de todo caso novo: em Configuração do caso, troque "Diretório do caso" para um diretório NOVO (ex.: results/cfd/caso_gui_001). ⚠️ O padrão aponta para o case_006 arquivado — clicar Preparar caso com esse diretório sobrescreve o caso arquivado.
  3. Conferir os campos — eles já abrem casados com o case_006: fonte Wiebe em origem model.json = examples/model_cfd_calibrated.json (a calibrada; a manual é model_cfd.json — não use), Rc 17, janela −120…+120°, P 127,6 kPa / T 308,15 K, paredes 440 K, kEpsilon, pistão móvel, 24×36 células, distribuição uniform, combustível diesel, PCI 39191,3, rpm 3396,2. Confirme ainda: "Distribuição WSL2" = Ubuntu-22.04 (a distro do solver); "Processos MPI do SOLVER" = 1 (paralelismo do solver, não do wiebepy); Estágios Wiebe: com origem model.json o calor vem do arquivo calibrado; com origem modelo atual a tabela editável 1–5 estágios aparece (a edição NÃO altera o modelo 0-D); Gás, numérica e comparação (equivalência completa com a CLI — mesmas chaves cfd.gas/cfd.numerics/cfd.comparison): Modelo do gás simple com Cp 1063,0 J/(kg·K) e M 28,96 ⇒ γ=1,370 = κ do 0-D (o padrão antigo Cp 1005 ⇒ γ=1,400), com μ e Pr editáveis; max_Co 0,25 (0,5 abortou neste motor, §5b do verification.md), Δt 1e-6 s, escrita a cada 10° CA; e o expander Comparação com o ensaio (diagnóstica) com o ensaio de referência (examples/data/ensaio_P_exp_carga3_45.txt, rad/bar, offset 0) — a sobreposição entra no report.html. Em Modelo do gás = multicomponent_inert (degrau R1) Cp/μ/Pr ficam desabilitados: N₂+O₂ com NASA janaf da mistura. Para descartar a comparação, esvazie o campo do arquivo.
  4. Preparar caso → gera o caso OpenFOAM para inspeção (estado Preparado). A configuração é validada antes: erros aparecem como mensagem vermelha e o caso não é gerado.
  5. Validar → estado Validado — o Executar exige isso (gate).
  6. Executar → painel com o log do solver ao vivo; ~2–3 min na malha 24×36. Cancelar execução interrompe inclusive os processos MPI, preservando logs e resultados parciais.
  7. Relatório HTML → gera/atualiza o report.html no diretório do caso (habilitado só no estado Concluído).
  8. Ver os resultados: o expander Resultados (0-D extraído do caso 3D) mostra p̄ máx, T̄ máx, trabalho indicado, perda nas paredes, a energia prescrita pela Wiebe com o erro da tabela, e o gráfico p̄×θ/T̄×θ. O relatório completo (proveniência, balanço de energia, limites) fica no report.html.

Dois detalhes que a GUI resolve sozinha: os campos de gás/numérica/ comparação abrem com os padrões da receita case_006 (não há mais a divergência Cp 1005 ⇒ γ=1,400 que cases preparados na GUI tinham antes desta equivalência); e o Estado do caso fica sempre visível no topo da página. O mesmo lembrete vale: a comparação com o ensaio no relatório é diagnóstica, nunca validação, e processo terminou ≠ convergiu — confira o fechamento de energia.

O modo reativo (combustão com mecanismo químico) está adiado para uma etapa posterior — não é proibido: aparece como indisponível até a implementação própria e nunca é substituído silenciosamente pela fonte Wiebe. Proposta incremental: docs/cfd/reactive_roadmap.md.

Fresta top-land (crevice_flow — submódulo opcional do CFD)

Módulo separado (wiebepy cfd crevice …, GUI na página CFD) que simula o gás entrando/saindo da folga entre o topo do pistão, a segmentação e o liner — não é simulação de blow-by: o fundo é fechado acima do 1º anel e a pressão da câmara é prescrita (tabela experimental ou sintética). O escoamento calculado não modifica essa pressão; não há fonte de calor nem química. Detalhes: docs/cfd/crevice.md.

wiebepy cfd crevice doctor   # confere OpenFOAM 13 (mesma checagem do cfd)
wiebepy cfd crevice prepare  --config examples/crevice/crevice_exemplo.yaml
wiebepy cfd crevice validate --case results/crevice_exemplo
wiebepy cfd crevice run      --case results/crevice_exemplo
wiebepy cfd crevice report   --case results/crevice_exemplo

Exporta séries p/T×θ, massa armazenada, fluxos assinados (entrada e saída acumulados separadamente), calor por parede e balanços de massa e energia com convenção de sinais declarada. O exemplo em examples/crevice/ usa dados sintéticos demonstrativos — não representam o ensaio. Sem a pasta crevice_flow, os modos 0-D, CFD e GUI continuam funcionando normalmente.

How the wiebepy CFD simulation works

The wiebepy CFD simulation solves the 3D compressible, transient flow inside the cylinder over the closed-valve interval, with combustion represented by a heat source prescribed by the 1-to-5-stage Wiebe function already calibrated against the pressure measurement.

The chain of steps is the following. First, the 0-D mode fits the measured pressure curve and returns the coefficients of each stage (β, θ0, Δθ, m, a) and the compression ratio. Those coefficients feed the heat source, which converts the burn rate into power:

Q̇(t) = mf · LHV · (dxb/dθ) · (dθ/dt),   with dθ/dt = 6 · rpm [°/s]

The derivative dxb/dθ comes from the same implementation used by the 0-D model, with no duplicated formulation.

The source is handed to the solver as a volumetric density q''' = Q̇/V₀(θ) rather than as total power, because that keeps it conservative with a moving mesh and in parallel runs: the solver applies the density over the current cell volumes. Closure is verified in every case by the identity ∫Q̇dt = mf·LHV·Δxb; in the example case the relative error is 2×10⁻⁴.

The conservation equations are solved by OpenFOAM 13 (foamRun, fluid solver), running under WSL2 or on Linux. The geometry is a simplified cylinder with a flat piston, whose slider-crank kinematics uses exactly the same parameters as the 0-D model. Time advance is controlled in crank angle, with steps between 0.01° and 0.5° and a maximum Courant number of 0.25.

At the end, wiebepy extracts the 0-D series (volume-averaged pressure, temperature, wall heat loss, indicated work) and produces a self-contained HTML report with provenance, balances and a comparison against the measurement by crank-angle band.

Scope, stated in every output: the burn rate is imposed, so chemical kinetics, flame front, knock and emissions are not resolved, and the comparison against the measurement is diagnostic, not independent validation, since the Wiebe function was calibrated with the same data. What CFD adds to the 0-D model is the spatial distribution of velocity, pressure and temperature, plus resolved wall heat transfer.

1. Installation

Requires Python 3.11 or newer (Windows, Linux or WSL2). Create a virtual environment before installing, inside the project folder:

cd wiebepy
python -m venv .venv
.venv\Scripts\activate            # Windows (Linux/WSL2: source .venv/bin/activate)
python -m pip install --upgrade pip
pip install -e ".[numba,dev]"     # core + Numba (fast on CPU) + pytest
pip install cupy-cuda12x          # optional: only with an NVIDIA card

Check:

wiebepy --devices                 # hardware and available backends
python -m pytest -m "not slow"    # fast tests (~20 s)
Without installing: inside the project folder, python main.py … does the same as wiebepy ….
“wiebepy is not recognized”: the package is not installed in the Python the terminal uses. Activate the .venv (the prompt shows (.venv)) and run pip install -e . again, or use python main.py. If PowerShell blocks activation, run once Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

2. First analysis

Evaluate a model without data, on a grid from −20° to 100°:

wiebepy --stages 3 --theta-min -20 --theta-max 100 --theta-step 0.1 --plot

Fit a model to the synthetic data shipped with the project:

wiebepy --stages 2 --optimize --input examples\data\synthetic_2stage.csv ^
        --fit-target xb --save-plots --output results\first

The screen shows the parameters of each stage, the objective of each run and the metrics (RMSE, R², AIC, BIC, Durbin-Watson). The true parameters of the synthetic data are in examples\data\true_parameters.json — compare them.

Ready-made commands for every case: wiebepy --help-examples.

2c. Fitting the PRESSURE curve (test data)

If your file holds crank angle × cylinder pressure (like the Double Wiebe test), use pressure mode: wiebepy fits the pressure with the same 0-D model as Double Wiebe, with 1 to 5 heat-release stages.

  1. GUI: Data page → Data type = Cylinder pressure; choose the angle unit (radians in the test file) and the pressure unit (bar); check the engine under “Engine (geometry and fuel)”.
  2. Fit page: choose N and click Start fit. The RMSE shown is the one from the solve_ivp reference.
  3. Comparison page: compare 1, 2 and 3 stages.
wiebepy --stages 2 --optimize --input test.txt --input-type pressure --pressure-unit bar
Loading a pressure file as “Burned fraction” raises an error: xb must lie between 0 and 1.

3. The model and its parameters

zj = (θ − θ0,j) / Δθj
xb(θ) = Σj βj [1 − exp(−aj zjmj+1)]   (term = 0 if θ < θ0,j)
dxb/dθ = Σj βj aj(mj+1)/Δθj · zjmj · exp(−aj zjmj+1)
ParameterMeaningUnitConstraint
β (beta)mass fraction burned in the stage–0 ≤ β ≤ 1, Σβ = 1
θ0 (theta0)start of the stage° (or rad)ordered during the fit
Δθ (duration)duration of the stage° (or rad)> 0
mshape (small = abrupt start)–> 0
aefficiency (6.908 ⇒ 99.9 % within Δθ)–fixed, or fitted with --fit-a

1 stage = single-Wiebe; 2 = double-Wiebe (premixed + diffusion); 3 to 5 stages represent additional phases (e.g. late burning). Full formulation: wiebepy --help-model.

4. Preparing the data

A .csv, .txt, .dat or .json file with the crank angle and the burned fraction and/or the burn rate:

theta,xb                theta,dxb_dtheta           theta,xb,dxb_dtheta,sigma
-20,0.000               -20,0.0000                 ...
-19,0.000               -19,0.0000
  • Separator detected automatically; lines starting with # are ignored.
  • Without a header: 2 columns = θ, xb; 3 columns = θ, xb, dxb/dθ.
  • Optional weight column (or sigma, with weight = 1/σ²), for --objective wrmse.
  • θ in degrees by default; use --angle-unit rad for radians.
  • xb must be normalized between 0 and 1 (the program warns otherwise).

5. Fitting N stages

wiebepy --stages 3 --optimize --input data.csv --runs 10 --save-plots --output results\fit3
OptionPurpose
--fit-target xb | dxb | bothseries being fitted; both uses the two, normalized (default: whichever is available)
--objective rmse | mse | mae | see | wrmseobjective function
--fit-aalso fits aj
--population, --iterationsPSO size (default 100 × 1000)
--runs, --seedindependent runs and seed (reproducible)
--config file.yamlall options in one file (see examples\)

Each run performs PSO followed by local refinement starting from the 5 best distinct points of the swarm. The final result is the best run.

6. Choosing the number of stages

wiebepy --compare-stages 1 2 3 4 5 --input data.csv --runs 10 --save-plots --output results\comparison

The program fits each N and shows a table with RMSE, MAE, SEE, R², ΔAIC, ΔBIC, Durbin-Watson, the cross-validation error and the number of warnings, followed by a recommendation.

Do not choose by the lowest RMSE. More stages always reduce the training error. The recommendation uses the smallest N whose cross-validation error stays within 5 % of the best one and that has no negligible or coincident stages. AIC/BIC are indicative: they assume independent residuals, which does not hold for xb curves. A Durbin-Watson ≈ 2 indicates the model already captures the structure of the data (residual ≈ noise).

Example with data from 3 true stages: RMSE keeps falling up to N = 5, but cross-validation levels off at N = 3, BIC is minimum at 3, and models 4 and 5 raise warnings about coincident stages — recommendation: 3-Wiebe.

7. Runs and warnings

Fitting several stages has local optima. That is why each fit performs several runs (default 5; for N ≥ 3 prefer 10 or more). The file run_statistics.csv shows best, mean, std, median and worst of the objective; parameters.csv brings the mean and the standard deviation of each parameter across runs.

Identifiability warnings (full list in warnings.txt):

WarningWhat it means
Stage 4 contributes less than 0.5%spare stage — use fewer stages
theta0_2 and theta0_3 are nearly identicaltwo stages start together; if “redundant”, they are practically the same
parameter m_5 reached upper boundthe optimum may lie outside the bounds — review them (bounds section)
varies strongly between runsparameter poorly determined by the data
strongly correlated (rho = …)two parameters compensate each other; do not read them in isolation

8. Parallel CPU and GPU

--backendDescription
auto (default)measures the available ones on your problem and uses the fastest
numbacompiled, with --workers threads — the fastest on CPU in our measurements
numpyvectorized, 1 core; with --runs and --workers the runs go to parallel processes
multiprocessingsplits the swarm across processes; only pays off on very large problems
cupy or --gpuNVIDIA GPU; pays off with large swarm × points

Without a GPU (or without CuPy/Numba) the program warns and uses the next available backend — it never stops because of that. Measure on your machine: wiebepy --benchmark --workers 8.

--precision float32 speeds up the GPU but makes the search less precise; use float64 (default) for final results.

10b. CFD (optional) — 3D flow in the cylinder

The CFD page (optional) builds and runs OpenFOAM 13 cases (on Windows, through WSL2) with heat release prescribed by the calibrated Wiebe function — 1 to 5 stages, fuels H₂, CH₄ (pure), ethanol and diesel. It does not predict chemical kinetics, flame front or emissions; the 3D results are conditioned on the Wiebe curve provided. The rest of the program does not depend on CFD, and disabling it does not erase results.

  1. Install the solver (once): OpenFOAM does not come from pip — pip install -e ".[cfd]" installs only Python dependencies (PyYAML).
    1. WSL2 — PowerShell as administrator (Windows 11): wsl --install -d Ubuntu-22.04, then wsl --version must list a WSL2 kernel (not WSL1). If it complains about virtualization, enable it in the UEFI/BIOS.
    2. OpenFOAM 13 inside Ubuntu 22.04 (official guide openfoam.org/download/linux): sudo sh -c "wget -O - https://dl.openfoam.org/gpg.key | apt-key add -"; sudo add-apt-repository http://dl.openfoam.org/ubuntu; sudo apt update && sudo apt install openfoam13.
    3. Verify: wiebepy cfd doctor lists the WSL2 distributions and, for each one, the detected OpenFOAM (/opt/openfoam*, foamRun, gcc, mpirun) and its version. Execution uses wsl.exe -d <distro> and the case is read/written directly in the project through /mnt/c/... — no copying needed. Without WSL2/solver only the CFD commands become unavailable (a diagnosis, never a silent fallback). Full guide (including native Linux): docs/cfd/install.md.
  2. Configure: engine (the same parameters as the 0-D modes), crank-angle window (closed valves), initial conditions, walls, turbulence, fuel and the origin of the Wiebe stages (current model or model.json).
  3. Prepare → case generated for inspection (Prepared state).
  4. Validate → checks files, geometry and solver (Validated state).
  5. Run → live solver log; Cancel run stops the MPI processes as well, preserving logs and partial results. Process finished ≠ converged: check the energy closure in the report.
  6. HTML report → self-contained file with full provenance (versions, parameters, mesh, scientific limits) and the results p̄×θ, T̄×θ, indicated work, wall heat loss and energy balance. Results are never presented as an independent prediction of combustion — the source is the prescribed Wiebe function.

Running an example — reference case (case_006)

To run an example you only edit one file; the other two are referenced by it. The 3 files involved:

FileRoleDo you edit it?
examples/config_cfd_equivalencia.yaml Case config (engine + CFD) — the only one the CLI receives Only for a new directory — otherwise use --output
examples/model_cfd_calibrated.json Wiebe source — already referenced inside the config (wiebe.model) No
examples/data/ensaio_P_exp_carga3_45.txt Experimental test for the diagnosis — already referenced (comparison.experimental) No

The sequence (4 commands + 1 check):

wiebepy cfd doctor                # 0. once: checks WSL2 + OpenFOAM 13
wiebepy cfd prepare  --config examples/config_cfd_equivalencia.yaml \
    --output results/cfd/my_case    # 1. builds the case (does NOT run it)
wiebepy cfd validate --case results/cfd/my_case   # 2. validates
wiebepy cfd run      --case results/cfd/my_case   # 3. runs (WSL2/OpenFOAM; ~2-3 min on the 24x36 mesh)
wiebepy cfd report   --case results/cfd/my_case   # 4. HTML report with p×θ, p×V and the comparison

--output overrides case_directory from the config — so you touch no file and do not overwrite the archived case_006. What each command produces:

  • prepare → a complete results/cfd/my_case/ (system/, constant/, 0/, case_config.yaml — the latter records EVERYTHING: source provenance, properties, energy, hypotheses); you can inspect it before running.
  • validate → the case state becomes Validated (only a validated case runs — the gate that already prevented path mistakes in case_013).
  • run → logs/foamRun.log, series under postProcessing/, state Completed.
  • report → report.html inside the case directory — that is the file you open in the browser.

Useful variants without editing files:

  • Without combustion (motored): add --no-heat to prepare.
  • Multicomponent (R1): needs its own config — copy examples/config_cfd_multicomponent.yaml (it already has gas.model: multicomponent_inert).
  • GUI: streamlit run src/wiebepy/gui/app.py → the CFD tab opens already matched to case_006; the buttons are the same four steps.

How to read the result: report.html compares against the measurement in a diagnostic way (same speed, same energy) — what it tells you is where and why the model departs from the measurement, not “the model was validated”.

Running an example in the graphical interface (GUI)

Opening it (requires pip install -e ".[gui]"): wiebepy --gui — opens in the browser (localhost:8501) — or streamlit run src/wiebepy/gui/app.py. Choose the CFD page in the menu. Step by step, with the buttons in order:

  1. Check the environment (once): in the Environment diagnosis (doctor) expander, button Run diagnosis — equivalent to wiebepy cfd doctor (checks WSL2, OpenFOAM, foamRun, mpirun). If OpenFOAM is installed but the code is not connected to it yet (the Connection line shows none), click Connect OpenFOAM to the code: the button detects the installation, verifies that foamRun really executes (a -help probe — directory detection may find a broken installation), stores the connection in ~/.wiebepy/cfd_env.json and adjusts the form's WSL2 distribution automatically — looking first in the configured distro and, if nothing is installed there, taking the best one from any distro. On the CLI the equivalent is wiebepy cfd doctor --connect. The connection survives a session restart (the default distro then comes from the stored connection).
  2. Choose the case directory — the first adjustment for every new case: under Case configuration, change “Case directory” to a NEW directory (e.g. results/cfd/gui_case_001). ⚠️ The default points to the archived case_006 — clicking Prepare case with that directory overwrites the archived case.
  3. Check the fields — they already open matched to case_006: Wiebe source with origin model.json = examples/model_cfd_calibrated.json (the calibrated one; the manual one is model_cfd.json — do not use it), Rc 17, window −120…+120°, P 127.6 kPa / T 308.15 K, walls 440 K, kEpsilon, moving piston, 24×36 cells, uniform distribution, diesel fuel, LHV 39191.3, 3396.2 rpm. Also confirm: “WSL2 distribution” = Ubuntu-22.04 (the solver's distro); “Solver MPI processes” = 1 (solver parallelism, not wiebepy's); Wiebe stages: with origin model.json the heat comes from the calibrated file; with origin current model the editable 1–5 stage table appears (editing it does NOT change the 0-D model); Gas, numerics and comparison (full equivalence with the CLI — the same cfd.gas/cfd.numerics/cfd.comparison keys): Gas model simple with Cp 1063.0 J/(kg·K) and M 28.96 ⇒ γ=1.370 = κ of the 0-D model (the old default Cp 1005 ⇒ γ=1.400), with editable μ and Pr; max_Co 0.25 (0.5 aborted on this engine, §5b of verification.md), Δt 1e-6 s, writing every 10° CA; and the Comparison against the measurement (diagnostic) expander with the reference test (examples/data/ensaio_P_exp_carga3_45.txt, rad/bar, offset 0) — the overlap goes into report.html. With Gas model = multicomponent_inert (step R1) Cp/μ/Pr are disabled: N₂+O₂ with NASA janaf for the mixture. To drop the comparison, clear the file field.
  4. Prepare case → builds the OpenFOAM case for inspection (Prepared state). The configuration is validated first: errors appear as a red message and the case is not generated.
  5. Validate → Validated state — Run requires it (gate).
  6. Run → panel with the live solver log; ~2–3 min on the 24×36 mesh. Cancel run stops the MPI processes as well, preserving logs and partial results.
  7. HTML report → creates/updates report.html in the case directory (enabled only in the Completed state).
  8. See the results: the Results (0-D extracted from the 3D case) expander shows p̄ max, T̄ max, indicated work, wall loss, the energy prescribed by the Wiebe function with the table error, and the p̄×θ/T̄×θ chart. The full report (provenance, energy balance, limits) is in report.html.

Two details the GUI handles by itself: the gas/numerics/comparison fields open with the case_006 recipe defaults (the Cp 1005 ⇒ γ=1.400 mismatch that GUI-prepared cases had before this equivalence is gone); and the Case state stays visible at the top of the page. The same reminder applies: the comparison against the measurement in the report is diagnostic, never validation, and process finished ≠ converged — check the energy closure.

Reactive mode (combustion with a chemical mechanism) is postponed to a later stage — it is not forbidden: it shows up as unavailable until its own implementation and is never silently replaced by the Wiebe source. Incremental proposal: docs/cfd/reactive_roadmap.md.

Top-land crevice (crevice_flow — optional CFD submodule)

A separate module (wiebepy cfd crevice …, GUI on the CFD page) that simulates the gas entering/leaving the gap between the piston top land, the rings and the liner — it is not a blow-by simulation: the bottom is closed above the first ring and the chamber pressure is prescribed (experimental or synthetic table). The computed flow does not modify that pressure; there is no heat source and no chemistry. Details: docs/cfd/crevice.md.

wiebepy cfd crevice doctor   # checks OpenFOAM 13 (same check as cfd)
wiebepy cfd crevice prepare  --config examples/crevice/crevice_exemplo.yaml
wiebepy cfd crevice validate --case results/crevice_exemplo
wiebepy cfd crevice run      --case results/crevice_exemplo
wiebepy cfd crevice report   --case results/crevice_exemplo

It exports p/T×θ series, stored mass, signed fluxes (inflow and outflow accumulated separately), heat per wall and mass/energy balances with a stated sign convention. The example in examples/crevice/ uses synthetic demonstration data — it does not represent the measured engine. Without the crevice_flow folder, the 0-D, CFD and GUI modes keep working normally.
