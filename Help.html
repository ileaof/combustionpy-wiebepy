1. Instalação

Requer Python 3.11 ou superior (Windows, Linux ou WSL2). Crie um ambiente virtual antes de instalar, dentro da pasta do projeto:

cd wiebepy
python -m venv .venv
.venv\Scripts\activate            # Windows (Linux/WSL2: source .venv/bin/activate)
python -m pip install --upgrade pip
pip install -e ".[numba,dev]"     # núcleo + Numba (rápido em CPU) + pytest
pip install cupy-cuda12x          # opcional: só com placa NVIDIA

Confira:

wiebepy --devices                 # hardware e backends disponíveis
python -m pytest -m "not slow"    # testes rápidos (~20 s)
Sem instalar: dentro da pasta do projeto, python main.py … faz o mesmo que wiebepy ….
“wiebepy não é reconhecido”: o pacote não está instalado no Python que o terminal usa. Ative o .venv (o prompt mostra (.venv)) e rode pip install -e . de novo, ou use python main.py. Se o PowerShell bloquear a ativação, rode uma vez Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

2. Primeira análise

Avalie um modelo sem dados, numa grade de −20° a 100°:

wiebepy --stages 3 --theta-min -20 --theta-max 100 --theta-step 0.1 --plot

Ajuste um modelo aos dados sintéticos que acompanham o projeto:

wiebepy --stages 2 --optimize --input examples\data\synthetic_2stage.csv ^
        --fit-target xb --save-plots --output results\primeiro

Na tela aparecem os parâmetros de cada estágio, o objetivo de cada run e as métricas (RMSE, R², AIC, BIC, Durbin-Watson). Os parâmetros verdadeiros dos dados sintéticos estão em examples\data\true_parameters.json — compare.

Comandos prontos para todos os casos: wiebepy --help-examples.

2b. Interface gráfica

pip install -e ".[gui]"     # uma vez: Streamlit
wiebepy --gui               # abre no navegador
  1. Dados: carregue seu arquivo ou um exemplo sintético.
  2. Modelo: escolha N e edite os parâmetros na tabela; os gráficos mostram xb, dxb/dθ e cada estágio sobre os dados.
  3. Ajuste: escolha N, a série e o número de runs e clique em Iniciar ajuste. O progresso aparece ao vivo; Cancelar interrompe. Depois, Aplicar ao modelo leva o resultado para a página Modelo.
  4. Comparação: escolha os N e clique em Comparar para ver a tabela e a recomendação.
  5. Exportar: baixe tudo num .zip.

O botão Ajuda, no topo da interface, abre este guia.

2c. Ajustar a curva de PRESSÃO (dados de ensaio)

Se o seu arquivo tem ângulo × pressão do cilindro (como o ensaio do Double Wiebe), use o modo pressão: o wiebepy ajusta a pressão com o mesmo modelo 0-D do Double Wiebe, com 1 a 5 estágios de liberação de calor.

  1. GUI: página Dados → Tipo de dado = Pressão do cilindro; escolha a unidade do ângulo (radianos no ensaio) e da pressão (bar); confira o motor em “Motor (geometria e combustível)”.
  2. Página Ajuste: escolha N e clique em Iniciar ajuste. O RMSE mostrado é o da referência solve_ivp.
  3. Página Comparação: compare 1, 2 e 3 estágios.
wiebepy --stages 2 --optimize --input ensaio.txt --input-type pressure --pressure-unit bar
Carregar um arquivo de pressão como “Fração queimada” dá erro: xb precisa estar entre 0 e 1.

3. O modelo e seus parâmetros

zj = (θ − θ0,j) / Δθj
xb(θ) = Σj βj [1 − exp(−aj zjmj+1)]   (termo = 0 se θ < θ0,j)
dxb/dθ = Σj βj aj(mj+1)/Δθj · zjmj · exp(−aj zjmj+1)
ParâmetroSignificadoUnidadeRestrição
β (beta)fração da massa queimada no estágio–0 ≤ β ≤ 1, Σβ = 1
θ0 (theta0)início do estágio° (ou rad)ordenados no ajuste
Δθ (duration)duração do estágio° (ou rad)> 0
mforma (pequeno = início abrupto)–> 0
aeficiência (6.908 ⇒ 99.9 % em Δθ)–fixo, ou ajustado com --fit-a

1 estágio = single-Wiebe; 2 = double-Wiebe (pré-misturada + difusão); 3 a 5 estágios representam fases adicionais (ex.: queima tardia). Formulação completa: wiebepy --help-model.

4. Preparar os dados

Arquivo .csv, .txt, .dat ou .json com o ângulo e a fração queimada e/ou a taxa de queima:

theta,xb                theta,dxb_dtheta           theta,xb,dxb_dtheta,sigma
-20,0.000               -20,0.0000                 ...
-19,0.000               -19,0.0000
  • Separador detectado automaticamente; linhas com # são ignoradas.
  • Sem cabeçalho: 2 colunas = θ, xb; 3 colunas = θ, xb, dxb/dθ.
  • Coluna weight (ou sigma, com peso = 1/σ²) opcional, para --objective wrmse.
  • θ em graus por padrão; use --angle-unit rad se estiver em radianos.
  • xb deve estar normalizado entre 0 e 1 (o programa avisa se não estiver).

5. Ajustar N estágios

wiebepy --stages 3 --optimize --input dados.csv --runs 10 --save-plots --output results\fit3
OpçãoPara quê
--fit-target xb | dxb | bothsérie ajustada; both usa as duas, normalizadas (padrão: as disponíveis)
--objective rmse | mse | mae | see | wrmsefunção objetivo
--fit-aajusta também aj
--population, --iterationstamanho do PSO (padrão 100 × 1000)
--runs, --seedruns independentes e semente (reprodutível)
--config arquivo.yamltodas as opções num arquivo (ver examples\)

Cada run faz PSO seguido de refinamento local a partir dos 5 melhores pontos distintos do enxame. O resultado final é o melhor run.

6. Escolher o número de estágios

wiebepy --compare-stages 1 2 3 4 5 --input dados.csv --runs 10 --save-plots --output results\comparacao

O programa ajusta cada N e mostra uma tabela com RMSE, MAE, SEE, R², ΔAIC, ΔBIC, Durbin-Watson, erro de validação cruzada e número de avisos, seguida de uma recomendação.

Não escolha pelo menor RMSE. Mais estágios sempre reduzem o erro de treino. A recomendação usa o menor N cujo erro de validação cruzada fica a até 5 % do melhor e que não tem estágios desprezíveis ou coincidentes. AIC/BIC são indicativos: supõem resíduos independentes, o que não vale para curvas de xb. Um Durbin-Watson ≈ 2 indica que o modelo já captura a estrutura dos dados (resíduo ≈ ruído).

Exemplo com dados de 3 estágios verdadeiros: o RMSE continua caindo até N = 5, mas a validação cruzada estabiliza em N = 3, o BIC é mínimo em 3 e os modelos 4 e 5 geram avisos de estágios coincidentes — recomendação: 3-Wiebe.

7. Runs e avisos

O ajuste de vários estágios tem ótimos locais. Por isso cada ajuste roda vários runs (padrão 5; para N ≥ 3 prefira 10 ou mais). O arquivo run_statistics.csv mostra best, mean, std, median e worst do objetivo; parameters.csv traz média e desvio de cada parâmetro entre runs.

Avisos de identificabilidade (lista completa em warnings.txt):

AvisoO que significa
Stage 4 contributes less than 0.5%estágio sobrando — use menos estágios
theta0_2 and theta0_3 are nearly identicaldois estágios começam juntos; se “redundant”, são praticamente o mesmo
parameter m_5 reached upper boundo ótimo pode estar fora dos limites — revise-os (seção bounds)
varies strongly between runsparâmetro mal determinado pelos dados
strongly correlated (rho = …)dois parâmetros se compensam; não interprete-os isoladamente

8. CPU paralela e GPU

--backendDescrição
auto (padrão)mede os disponíveis com o seu problema e usa o mais rápido
numbacompilado, com --workers threads — o mais rápido em CPU nas medições
numpyvetorizado, 1 núcleo; com --runs e --workers, os runs rodam em processos paralelos
multiprocessingdivide o enxame entre processos; só compensa em problemas muito grandes
cupy ou --gpuGPU NVIDIA; compensa com enxames × pontos grandes

Sem GPU (ou sem CuPy/Numba) o programa avisa e usa o próximo backend disponível — nunca para por isso. Meça na sua máquina: wiebepy --benchmark --workers 8.

--precision float32 acelera a GPU, mas torna a busca menos precisa; use float64 (padrão) para resultados finais.

10b. CFD (opcional) — escoamento 3D no cilindro

Página CFD (opcional): gera e executa casos OpenFOAM 13 (no Windows, via WSL2) com a liberação de calor prescrita pela Wiebe calibrada — 1 a 5 estágios, combustíveis H₂, CH₄ (puro), etanol e diesel. Não prevê cinética química, frente de chama nem emissões; os resultados 3D são condicionados à curva Wiebe informada. O restante do programa não depende do CFD, e desabilitá-lo não apaga resultados.

  1. Instalar o solver (uma vez): wsl --install -d Ubuntu-22.04 e o OpenFOAM 13 dentro dela — guia em docs/cfd/install.md. Sem solver, só os comandos CFD ficam indisponíveis (o doctor diagnostica).
  2. Configurar: motor (mesmos parâmetros dos modos 0-D), janela angular (válvulas fechadas), condições iniciais, paredes, turbulência, combustível e origem dos estágios Wiebe (modelo atual ou model.json).
  3. Preparar → caso gerado para inspeção (estado Preparado).
  4. Validar → verifica arquivos, geometria e solver (estado Validado).
  5. Executar → log do solver ao vivo; Cancelar execução interrompe inclusive os processos MPI, preservando logs e resultados parciais. Processo terminou ≠ convergiu: confira o fechamento de energia no relatório.
  6. Relatório HTML → arquivo autônomo com proveniência completa (versões, parâmetros, malha, limites científicos) e os resultados p̄×θ, T̄×θ, trabalho indicado, perda às paredes e balanço de energia. Os resultados nunca são apresentados como predição independente de combustão — a fonte é a Wiebe prescrita.

O modo reativo (combustão com mecanismo químico) existe apenas como arquitetura — aparece como indisponível e nunca é substituído silenciosamente pela fonte Wiebe. Detalhes: docs/cfd/.
